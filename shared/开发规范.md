## 一、代码风格与组织

### 1.1 命名约定：全项目统一 `snake_case`（含局部变量与函数名）

**结论：不混用 `camelCase`。** 理由三条：

1. **协议字段是 `snake_case` 且不可改**。`protocol.md` 规定全篇 JSON 字段统一 `snake_case`，§5 的签名串又直接拼接这些字段。改用 `camelCase` 就要在每个模块维护一层映射，**映射写错即签名失败或字段丢失**，而签名失败按契约是 fail-closed 停机。
2. **术语表与数据库字段已是 `snake_case`**：`account_day_index`、`min_interval_ms`、`send_id`、`user_key_hash`。混用会产生"同一概念两种写法"，这正是契约漂移的起点。
3. **旧代码是 `camelCase`**（`awemeId`、`commentId`、`doneAt`），新代码是重写，必须一次斩断。**`legacy/` 之外出现 `awemeId` 这类写法视为缺陷。**

| 对象 | 约定 | 正例 | 反例 |
|---|---|---|---|
| 变量/参数/对象属性 | `snake_case` | `daily_max`、`clock_skew_ms` | `dailyMax` |
| 函数/方法 | `snake_case`，动词开头 | `settle_send_batch()` | `settleSendBatch()` |
| 类 | `PascalCase` | `class BrowserHost` | `class browser_host` |
| 常量/枚举表 | `UPPER_SNAKE_CASE`（值仍小写） | `ERROR_CODES = { ELEMENT_TIMEOUT: 'element_timeout' }` | `errorCodes` |
| 模块文件名 | `kebab-case.js` 小写 | `browser-host.js`、`stable-stringify.js` | `browserHost.js` |
| 数据库表 | 单数 `snake_case`，SQL 关键字大写 | `send_log(account_id, send_id, verdict)` | `SendLog` |
| 协议字段 | 照抄 `protocol.md`，**不改名、不加前缀** | `sent_at_ms`、`confirm_signal` | `sentAtMs` |
| 时间字段 | 统一 `_ms` 后缀，Unix 毫秒整数 | `sent_at_ms`、`cooldown_until_ms` | `sentAt` |
| 金额/积分 | 统一 `_milli` 后缀，整数 | `balance_milli`、`charged_milli` | `balance` |
| 哈希字段 | 统一 `_hash` 后缀 | `content_hash`、`user_key_hash` | `userKey` |
| 布尔字段 | 形容词/分词，**禁止 `is_`/`has_`** | `sending_enabled`、`collect_only`、`applied` | `isSending` |
| 私有内部函数 | 前置 `_` 且不导出 | `_normalize_text()` | — |
| HTTP 头 / DOM 属性 | 照抄原文 | `X-Lic-Sign`、`data-e2e` | `x-lic-sign` |

### 1.2 文件与模块划分

| 约束 | 数值 | 说明 |
|---|---|---|
| 单文件行数 | **≤ 500**（硬上限 600） | 旧 `reply_server/server.js` 把路由/静态服务/子进程编排/队列混在一起，是 D-13"重复点击静默杀掉任务"的成因之一 |
| 单函数行数 | **≤ 60**；嵌套 ≤ 4 层 | 超限说明职责混杂，先拆再写 |
| 单文件导出 | **≤ 12 个** | 导出爆炸意味着该模块该拆成"原语 + 编排"两层 |
| 圈复杂度 | ≤ 15 | 大量 if-else 改查表（见 §2.1 的 `ERROR_CODES`） |

**划分原则**：

1. 一个模块只做一件事。`safety/guard.js` 只管限额判定，**不**发请求、不写盘、不打文件日志；返回判定结果，由调用方决定后续。
2. 依赖方向单向：`adapters/ → platform/ → core/`，`host/ → 全部`。**禁止反向 require**（`core/` 不得 require `adapters/`）。
3. `legacy/` 不得被任何生产代码 `require`；`license-server/` 与 `client/` **不得互相 require**（只能走 HTTP 契约）；双端共享代码只许放 `shared/lib/`。
4. **选择器只允许定义在 `client/platform/selectors.js`**，其他文件出现 `data-e2e` 字符串视为缺陷（S-4 要求改版时只改 1 个文件）。
5. **安全数值只允许来自服务端 `policy`**，代码中出现 `10`/`25`/`30`/`70`/`12600`/`0.85` 这类限额常量视为缺陷（红线 1）。
6. **禁止** `utils.js` / `helpers.js` / `common.js`。工具函数按用途命名（`stable-stringify.js`、`atomic-write.js`、`mask.js`）。

### 1.3 CommonJS require 顺序

固定四段，段间空行，段内按变量名字母序：

```js
const crypto = require('node:crypto')                 // 1) Node 内置，必须带 node: 前缀
const fs = require('node:fs')
const WebSocket = require('ws')                       // 2) 白名单第三方（全项目只有 ws）
const { ERROR_CODES, STAGES } = require('../../shared/lib/errors')   // 3) 跨目录共享
const { atomic_write_json } = require('./atomic-write')              // 4) 本项目模块（相对路径）
```

**禁止**：`require` 绝对路径（旧代码 D-1 的根因）；模块顶层产生副作用（读写文件、发网络请求、起定时器）；`require(用户输入)`；动态 `import()`。

### 1.4 禁止事项（硬性）

| 禁止 | 说明 |
|---|---|
| TypeScript / JSX / 装饰器 / 类型注解 | 纯 JavaScript CommonJS。无构建步骤是"解压即用"分发的前提；`node --check` 必须直接通过 |
| `eval` / `new Function` / `vm` | 含"用 eval 解析配置"。**例外**：`Runtime.evaluate` 的表达式是发给 Chrome 的字符串，属允许，但必须来自 `selectors.js` 或页面模型，不得拼接用户输入 |
| 白名单外依赖 | 白名单**只有 `ws`**，服务端零第三方依赖。见 §8 |
| `puppeteer-core` / `playwright` | 见 §8.2 |
| 硬编码绝对路径 | 一律 `path.join(WORKSPACE, ...)`，`WORKSPACE` 由 `REPLY_WORKSPACE` 解析。旧代码 5 文件 13 处硬编码 `D:\deep seek\` 造成 D-1 阻断级缺陷 |
| `try { } catch { }` 空捕获 | 见 §2.2，**本规范最重要的一条** |
| `process.exit(1)` 处理顶层异常 | 见 §2.6 |
| `rejectUnauthorized: false` | 生产强制校验 TLS 证书 |
| 日志/上报中出现禁用字段 | 见 §3.3 |
| `console.log` 打业务日志 | 统一走 `shared/lib/log.js`；`console.*` 只允许用于 `cli.js` 的交互输出 |

## 二、错误处理规范

> 对应稳定指标 **S-3（任何失败都能定位到具体阶段与原因）**。这是本项目最关键、也最容易被违反的规范。

### 2.1 统一错误对象结构

所有跨层传递的失败必须是同一结构，唯一构造函数在 `shared/lib/errors.js`：

```js
// shared/lib/errors.js
const STAGES = {
  SCHEDULE: 'schedule',           // 调度：额度/频控/急停/熔断判定
  OPEN_PAGE: 'open_page',         // 打开目标页/切换标签页
  EXPAND_PANEL: 'expand_panel',   // 展开评论面板/输入区
  LOCATE: 'locate',               // 定位元素（选择器未命中在此层）
  INTERACT: 'interact',           // 点击/输入/按键
  VERIFY: 'verify',               // 成功判定（嗅探平台响应）
  PERSIST: 'persist',             // 本地落盘
  REPORT: 'report',               // 上报授权中心
}
const RETRY_CLASS = { TRANSIENT: 'transient', PERMANENT: 'permanent', SECURITY: 'security' }

// code → 默认处理方式。处理策略集中在此，不在业务代码里散落 if
const ERROR_CODES = {
  NET_TIMEOUT:             { stage: STAGES.REPORT,   retry: RETRY_CLASS.TRANSIENT, backoff: true },
  NET_REFUSED:             { stage: STAGES.REPORT,   retry: RETRY_CLASS.TRANSIENT, backoff: true },
  SERVER_DB_BUSY:          { stage: STAGES.REPORT,   retry: RETRY_CLASS.TRANSIENT, backoff: true, max_retry: 3 },
  RESP_SIGN_MISSING:       { stage: STAGES.REPORT,   retry: RETRY_CLASS.SECURITY, halt: true },   // fail-closed
  RESP_SIGN_INVALID:       { stage: STAGES.REPORT,   retry: RETRY_CLASS.SECURITY, halt: true },
  LOGIN_PROOF_INVALID:     { stage: STAGES.REPORT,   retry: RETRY_CLASS.SECURITY, halt: true },
  RESP_TS_SKEW:            { stage: STAGES.REPORT,   retry: RETRY_CLASS.SECURITY, max_retry: 1 },
  AUTH_TS_SKEW:            { stage: STAGES.REPORT,   retry: RETRY_CLASS.TRANSIENT, max_retry: 1 }, // 校准后只重试 1 次
  AUTH_REPLAY:             { stage: STAGES.REPORT,   retry: RETRY_CLASS.SECURITY, halt: true },
  POLICY_VIOLATION:        { stage: STAGES.SCHEDULE, retry: RETRY_CLASS.PERMANENT },
  POLICY_SENDING_DISABLED: { stage: STAGES.SCHEDULE, retry: RETRY_CLASS.PERMANENT, halt: true },
  POLICY_CIRCUIT_OPEN:     { stage: STAGES.SCHEDULE, retry: RETRY_CLASS.PERMANENT, halt: true },
  QUOTA_EXHAUSTED:         { stage: STAGES.SCHEDULE, retry: RETRY_CLASS.PERMANENT },
  MIN_INTERVAL_NOT_REACHED:{ stage: STAGES.SCHEDULE, retry: RETRY_CLASS.TRANSIENT },
  SELECTOR_MISS:           { stage: STAGES.LOCATE,   retry: RETRY_CLASS.TRANSIENT, max_retry: 3 }, // reason 必带选择器 key
  ELEMENT_ZERO_SIZE:       { stage: STAGES.LOCATE,   retry: RETRY_CLASS.TRANSIENT, max_retry: 3 }, // 隐藏结构误命中
  ELEMENT_TIMEOUT:         { stage: STAGES.LOCATE,   retry: RETRY_CLASS.TRANSIENT, max_retry: 3 },
  TAB_CLOSED:              { stage: STAGES.OPEN_PAGE, retry: RETRY_CLASS.TRANSIENT, max_retry: 2 },
  PANEL_NOT_EXPANDED:      { stage: STAGES.EXPAND_PANEL, retry: RETRY_CLASS.TRANSIENT, max_retry: 2 },
  NOTE_POST_UNSUPPORTED:   { stage: STAGES.EXPAND_PANEL, retry: RETRY_CLASS.PERMANENT },
  EMPTY_RESPONSE:          { stage: STAGES.VERIFY,   retry: RETRY_CLASS.PERMANENT, circuit: 'risk_control' },
  PLATFORM_REJECTED:       { stage: STAGES.VERIFY,   retry: RETRY_CLASS.PERMANENT, circuit: 'platform_reject' },
  PUBLISH_NOT_CAPTURED:    { stage: STAGES.VERIFY,   retry: RETRY_CLASS.TRANSIENT, max_retry: 1 },
  DISK_WRITE_FAILED:       { stage: STAGES.PERSIST,  retry: RETRY_CLASS.TRANSIENT, max_retry: 3 },
}

class WorkbenchError extends Error {
  constructor(code, { stage, reason, context = {}, cause = null } = {}) {
    super(code)
    this.name = 'WorkbenchError'
    this.code = code            // 大写下划线：契约错误码，只允许照抄 protocol.md §3.2
    this.stage = stage          // STAGES 之一：失败阶段（S-3 的核心）
    this.reason = reason        // 小写 snake_case：本地归因码，比 code 更细
    this.context = context      // 最小必要上下文，禁止塞原始内容（§3.3）
    this.cause = cause          // 原始异常，仅本地日志
    this.at_ms = Date.now()     // 仅诊断；上报字段用校准后时间
  }
  to_log() { return { code: this.code, stage: this.stage, reason: this.reason, context: this.context } }
}
const fail = (code, meta) => { throw new WorkbenchError(code, meta) }
module.exports = { STAGES, RETRY_CLASS, ERROR_CODES, WorkbenchError, fail }
```

**两个命名空间不得混用**：契约错误码 `code`（大写下划线，只许照抄 `protocol.md` §3.2）与本地归因码 `reason`（小写下划线，可扩充，必须在 `errors.js` 登记）。`verdict` / `failure_reason` 是**闭集**，只能取 `protocol.md` §7.2 / §7.4 的枚举，未知键会导致服务端拒绝整条上报。

### 2.2 ⚠️ 禁止空 catch（本项目最贵的一次教训）

**旧代码事实**（`reply_worker.js:490-494`）：

```js
// ❌ 绝对禁止复制
try {
  let hist = []
  try { hist = JSON.parse(fs.readFileSync("D:\\deep seek\\replied_history.json", "utf8")) } catch {}
  if (!hist.includes(String(item.commentId))) { hist.push(String(item.commentId)); fs.writeFileSync(/* … */) }
} catch {}          // ← 去重历史从未落盘；同一评论被重复回复，且无任何日志
```

因 D-1 的硬编码路径在非原作者机器上不存在，写盘**每次都失败却被静默吞掉**，调用方认为"已记录"。后果：去重历史永远为空 → 同一评论被重复回复 → 触发平台风控 → 且因为没有任何日志，排障时找不到原因。**空 catch 把功能缺陷伪装成了正常运行。**

**正确写法（三选一，禁止第四种）**：

```js
// ✅ A：失败升级为可归因错误，由调用方决定是否降级（用于安全前提类的写盘）
async function remember_replied(comment_id) {
  try {
    await store.update('replied_history.json', (d) => {
      if (!d.comment_ids.includes(comment_id)) d.comment_ids.push(comment_id)
      return d
    })
  } catch (cause) {
    fail('DISK_WRITE_FAILED', { stage: STAGES.PERSIST, reason: 'replied_history_write_failed',
      context: { comment_id_hash: hash_prefix(comment_id, salt), file: 'replied_history.json' }, cause })
  }
}
// ✅ B：确属可忽略的清理动作，必须显式声明忽略理由 + 计数 + warn 日志
try { await browser_host.close_target(target_id) }
catch (cause) {
  metrics.count('cleanup_error', { target: 'close_tab' })   // 关不掉不影响业务：巡检会回收
  log.warn('cleanup_failed', { stage: STAGES.OPEN_PAGE, reason: 'close_tab_failed', cause: cause.message })
}
// ✅ C：可选功能缺失（如 Python 清洗脚本）→ 显式跳过 + info 日志 + 返回 null
try { return require_optional('scrapling_bridge') }
catch { log.info('python_bridge_skipped', { reason: 'python_absent' }); return null }
```

**自检命令**（提交前必跑，必须输出 `EMPTY_CATCH_TOTAL 0`）：

```bash
node test/lint-empty-catch.js
```

### 2.3 错误码分层与处理方式

| 层 | 典型码 | 谁能发现 | 处理方式 |
|---|---|---|---|
| **网络** | `NET_TIMEOUT` `NET_REFUSED` `SERVER_DB_BUSY` | `license/` HTTP 层 | 不算业务失败；指数退避重试；进入离线降级；**不改变本地额度与策略** |
| **协议** | `RESP_SIGN_INVALID` `AUTH_REPLAY` `AUTH_TS_SKEW` `LOGIN_PROOF_INVALID` | `license/sign.js` | **fail-closed**：记安全事件 → 立即暂停发送 → 退避重试登录。**绝不认为余额充足、绝不认为策略放宽** |
| **策略** | `POLICY_VIOLATION` `POLICY_SENDING_DISABLED` `POLICY_CIRCUIT_OPEN` `QUOTA_EXHAUSTED` | `safety/guard.js` | 本地拦截，**不发起发送**；写成 `audit_config_changes` 证据（`applied=false` + `reject_code`）；按 `cooldown_until_ms` 等待 |
| **计费** | 结算响应 `billing_status` | `license/reporter.js` | 只以服务端响应为准；`billed` 才减影子额度；`unbilled_insufficient_credit` **不得重试、不得本地补扣** |
| **平台** | `EMPTY_RESPONSE` `PLATFORM_REJECTED` | `platform/publish-verifier.js` | `verdict=failed` + `risk_control_signal="empty_response"`；**不计费**；计入熔断判据 |
| **DOM 定位** | `SELECTOR_MISS` `ELEMENT_ZERO_SIZE` `ELEMENT_TIMEOUT` | `platform/` 页面模型 | 可重试 ≤3 次；`reason` **必须带选择器 key**（`selector_miss:comment_list`），这是改版定位（S-4）的唯一线索 |
| **落盘** | `DISK_WRITE_FAILED` | `host/store.js` | 重试 3 次；仍失败则任务回退 `queued` 并告警，**不得进入下一步** |

### 2.4 每个失败必须能定位到"阶段 + 原因"

任务维护一条阶段轨迹，UI 直接显示"卡在哪一步、为什么"：

```js
const steps = []
async function step(stage, fn) {
  const t0 = process.hrtime.bigint()                     // 单调时钟，不用 Date.now 差值
  try {
    const value = await fn()
    steps.push({ stage, ok: true, cost_ms: Number(process.hrtime.bigint() - t0) / 1e6 })
    return value
  } catch (e) {
    steps.push({ stage, ok: false, code: e.code || 'UNKNOWN', reason: e.reason || 'unknown',
                 cost_ms: Number(process.hrtime.bigint() - t0) / 1e6 })
    throw e                                              // 不吞、不包装成新错误丢失 stage
  }
}
await step(STAGES.OPEN_PAGE, () => page.open(video_url))
await step(STAGES.EXPAND_PANEL, () => page.expand_comment_panel())   // note 帖在此抛 NOTE_POST_UNSUPPORTED
await step(STAGES.LOCATE, () => page.locate_comment(target))
await step(STAGES.INTERACT, () => page.type_and_submit(reply_text))
const evidence = await step(STAGES.VERIFY, () => publish_verifier.wait_for_platform_response())
```

失败时日志输出 `{ task_id, source_type, stage, reason, steps }`。

### 2.5 重试 / 熔断 / 上报决策表

| 情形 | 重试 | 退避 | 熔断 | 上报 |
|---|---|---|---|---|
| 网络超时、连接被拒 | 是 | 指数 1s→2s→4s…上限 60s | 否 | 否（本地日志） |
| `SERVER_DB_BUSY`(503) | 是，≤3 次 | 固定 1s | 否 | 否 |
| `SERVER_UNAVAILABLE` / 维护中 | 是 | 指数 + 抖动 | 否 | 进入离线降级，囤 `pending_sends.json`，恢复后补报 |
| 响应验签失败 / `AUTH_SIGN_*` | **否** | — | **是（立即暂停）** | 是（安全事件必报） |
| `AUTH_TS_SKEW` | **只 1 次**（先用 `server_time_ms` 校准） | 立即 | 否 | 否 |
| `AUTH_REPLAY` | 否 | — | 是（重新登录后重试） | 是 |
| `POLICY_VIOLATION` | 否 | — | 否 | **是**（"用户主动调高被拒"的关键证据） |
| `POLICY_DAILY_CAP_EXCEEDED`(200) | 否 | — | 否 | 明细照报（留痕不计费），客户端立即降到上限内 |
| `POLICY_SENDING_DISABLED` | 否 | — | 是（停到次日/解除） | 是 |
| `POLICY_CIRCUIT_OPEN` | 否 | 等 `cooldown_until_ms` | 是 | 否（熔断期不上报新明细；历史补报照常） |
| `CREDIT_EXHAUSTED`(402) | 否 | 每 5 分钟重试心跳 | 是（暂停态） | 是（UI 提示 + 展示 `quota_notice`） |
| `SELECTOR_MISS` / `ELEMENT_TIMEOUT` | 是，≤3 次 | 1s / 2s / 4s | 连续 3 次同类失败 → 暂停该来源 | 是（`failure_reason=element_timeout`） |
| 空响应 | **否** | — | 是，风险码冷却（默认 24h） | 是（`risk_control_rejected`） |
| 失败率 > `failure_rate_threshold`(0.4)（窗口 20） | — | — | 是，30 分钟 | 是 |
| 平台拒绝计数 ≥ 3 | — | — | 是 | 是 |
| `AUDIT_SEND_INVALID` / `REPORT_INVALID` | 否 | — | 否 | 丢弃该条 + 本地 ERROR 日志 |
| `AUDIT_SEND_CONFLICT` | 否 | — | 否 | 丢弃 + **立即告警**（客户端 bug） |
| `SERVER_VERSION_UNSUPPORTED`(426) | 否 | — | 是（停机） | 展示强制升级页 |

### 2.6 ⚠️ 顶层异常不得 `process.exit(1)`

**旧代码事实**：`reply_worker.js:530` 是 `})().catch((e) => { console.error("FATAL:", e.message); process.exit(1) })`——退出后**没有任何人重启它**，采集与回复静默停止，而商家界面仍显示"运行中"。违反 S-1（72 小时不崩溃）。

```js
// host/main.js 顶层兜底（三层，缺一不可）
process.on('uncaughtException', (err) => {
  log.error('uncaught_exception', { stage: 'top', reason: classify(err), stack: err.stack })
  recover_running_tasks('uncaught_exception')        // sending → queued，带 attempt_seq
  if (is_fatal(err)) shutdown_gracefully('fatal')    // 仅端口占用、磁盘只读等无法继续的情形
})
process.on('unhandledRejection', (reason) => {
  log.error('unhandled_rejection', { stage: 'top', reason: classify(reason) })
  recover_running_tasks('unhandled_rejection')
})
async function main_loop() {
  while (!shutdown_requested) {
    try { await tick() }
    catch (e) {
      log.error('tick_failed', { ...new WorkbenchError(e.code || 'UNKNOWN', e).to_log(), stack: e.stack })
      recover_running_tasks('tick_failed')
      await sleep(backoff_next())                    // 1s→2s→…上限 60s，成功一次即复位
    }
  }
}
```

`recover_running_tasks()` 的硬要求：**不得重新生成 `send_id`**。崩溃前已落盘的 `send_id` 必须复用，否则重发无法幂等、会被重复计费（红线 2）。

## 四、客户端存储规范（硬约束）

### 4.1 ⚠️ 单写者（不可协商）

**只有 `client/host/` 主进程读写实例 JSON 文件。** `browser-host`、`platform`、`adapters`、`license`、UI **不得**去碰实例数据文件，必须经 IPC 请求 host 代读写。

**旧代码事实**：`reply_worker.js:479-481` 用"循环开头读到的陈旧 `q`"全量覆写抢占任务，而 `reply_server/server.js:642-661` 同时在读-改-写追加新任务 → 抢单瞬间商家入队的新任务**被静默抹掉**（D-7）。同类还有 `live_config.json` 三写者、`scan_comments.js` 与 `pipeline.js` 同时覆写同一评论库（D-10）。根因都是**多进程无锁覆写同一文件**。

```js
// client/host/store.js —— 唯一写入口
const SCHEMA_VERSION = { 'reply_queue.json': 2, 'replied_history.json': 1, 'pending_sends.json': 2,
                         'policy.json': 1, 'license_state.json': 1, 'leads.json': 1 }
const cache = new Map()   // file → 最新内存态（单写者持有的唯一真相）
const chain = new Map()   // file → Promise 链，保证同文件写入串行化

function atomic_write_json(abs_path, obj) {                   // 原子写：.tmp-<pid> → fsync → rename
  const tmp = abs_path + '.tmp-' + process.pid
  const fd = fs.openSync(tmp, 'w')
  try {
    fs.writeFileSync(fd, JSON.stringify(obj, null, 2), 'utf8')
    fs.fsyncSync(fd)               // 必须先 fsync 再 rename，否则断电可能得到空文件
  } finally { fs.closeSync(fd) }
  fs.renameSync(tmp, abs_path)     // 同目录 rename 原子；Windows 上也会覆盖已存在文件
}

function load(instance_dir, file) {
  const abs = path.join(instance_dir, file), empty = { schema_version: SCHEMA_VERSION[file] }
  let data
  try { data = JSON.parse(fs.readFileSync(abs, 'utf8')) }
  catch (e) {
    if (e.code === 'ENOENT') { cache.set(abs, empty); return empty }        // 首次运行：不是错误
    fs.renameSync(abs, abs + '.corrupt-' + Date.now())                      // 损坏：留现场，绝不当作空文件
    fail('DISK_WRITE_FAILED', { stage: STAGES.PERSIST, reason: 'json_corrupt', context: { file } })
  }
  data = migrate(file, data)
  cache.set(abs, data)
  return data
}

function migrate(file, data) {                    // 迁移链：逐步升级，每步必须是纯函数、禁止访问网络
  const target = SCHEMA_VERSION[file]
  let v = Number(data.schema_version || 0)
  if (v > target) fail('DISK_WRITE_FAILED', { stage: STAGES.PERSIST, reason: 'schema_too_new', context: { file, v, target } })
  for (const s of (MIGRATIONS[file] || [])) if (v === s.from) { data = s.up(data); v = s.to }
  data.schema_version = target
  return data
}

function update(instance_dir, file, mutator) {    // 读-改-写：永远以最新内存态为基准
  const abs = path.join(instance_dir, file)
  const next = (chain.get(abs) || Promise.resolve()).then(() => {
    const latest = cache.get(abs) || load(instance_dir, file)   // ← 先取最新，绝不用陈旧对象
    const draft = mutator(structuredClone(latest))
    atomic_write_json(abs, draft)                               // ← 再整体原子落盘
    cache.set(abs, draft)
    return draft
  })
  chain.set(abs, next.catch(() => {}))            // 失败不阻断后续写入
  return next
}
module.exports = { load, update, atomic_write_json }
```


**回退语义（S-5 关键）**：进程重启后 `sending` 态任务必须回退为 `queued`，且**保留原 `send_id` 与 `attempt_seq`**（`attempt_seq += 1`）。重新生成 `send_id` 会导致同一发送被计费两次。

### 5.2 ⚠️ 事务边界：扣费与流水必须在同一事务内

这是 `docs/架构说明.md` §五的硬约束，也是红线 2 的落地形态。**扣减余额、写 `send_log`、写 `credit_ledger` 三者必须原子完成**——否则会出现"扣了钱没流水"（无法对账）或"有流水没扣钱"（少收钱）。

```js
// license-server/domain/billing.js（对应 protocol.md §6.4）
db.exec('BEGIN IMMEDIATE')                          // 立即取写锁，避免升级锁失败
try {
  for (const s of sort_by_sent_at(batch.sends)) {   // 严格按 sent_at_ms 升序
    const prev = find_send(acc.account_id, s.send_id)
    if (prev && prev.verdict === 'sent_confirmed') { results.push(dup_result(s)); continue }
    if (prev && !is_upgrade(prev, s)) { results.push(reject_result(s, 'AUDIT_SEND_CONFLICT')); continue }

    const quota = day_quota(acc, s.source_type, s.sent_at_ms)      // 按该条 sent_at_ms 所属自然日
    const over_limit = quota.max === 0 || quota.used >= quota.max  // 观察期 max=0，一律超限
    const billable = s.verdict === 'sent_confirmed'
      && s.evidence.confirm_signal === 'platform_response'
      && s.evidence.platform_status_code === 0
      && !over_limit && !acc.insufficient                          // ← 五条必须同时成立

    insert_send_log(s, over_limit)                                 // 明细永远留痕（审计优先于计费）
    let charged_milli = 0
    if (billable && (acc.balance_milli >= unit_milli || !acc.insufficient)) {
      acc.balance_milli -= unit_milli                              // §6.5 允许跨零点唯一一次透支
      charged_milli = unit_milli
      if (acc.balance_milli < 0) acc.insufficient = true
      update_credit(acc.account_id, acc.balance_milli, now_ms)     // ↓ 同一事务内：扣费 + 流水
      insert_ledger(acc.account_id, 'usage', -charged_milli, acc.balance_milli, s.send_id, now_ms)
    }
    results.push(build_result(s, over_limit, charged_milli))
  }
  if (acc.balance_milli <= 0) mark_state(acc.account_id, 'exhausted')
  db.exec('COMMIT')
} catch (e) { db.exec('ROLLBACK'); throw e }      // 必须回滚，绝不"部分成功"
```

**事务铁律**：① 事务内**禁止任何 I/O**（不发 HTTP、不写文件、不 `await` 网络；`DatabaseSync` 是同步 API，混入异步会长时间持锁）；② 一律 `BEGIN IMMEDIATE`，不用裸 `BEGIN`；③ 必须 `try/catch` + 显式 `ROLLBACK` 后 `throw`，禁止 `catch { }`；④ 事务内禁止 `process.exit`；⑤ SQLite 忙返回 `SERVER_DB_BUSY`(503)，客户端 1 秒后重试 ≤3 次。

## 六、网络与协议实现规范

### 6.1 时间：一律 Unix 毫秒 `_ms`

```js
// license/clock.js
let clock_skew_ms = 0
const sync_from_response = (server_time_ms, sent_at_wall_ms) => { clock_skew_ms = server_time_ms - sent_at_wall_ms }
const now_ms = () => Date.now() + clock_skew_ms                                   // 用于所有上报字段
const monotonic_ms = () => Number(process.hrtime.bigint() / 1000000n)             // 用于耗时
```

**客户端墙上时间不可信**（每个响应带 `server_time_ms`）。铁律：`clock_skew_ms` 只用于**填写上报字段**；**时长计算一律用单调时钟**，绝不用 `Date.now()` 差值（会被 NTP 跳变污染）。自然日边界（日上限、等级天数）按 `stats_tz_offset_minutes`（默认 480 = UTC+8）划分，**客户端不得用本地时区自行推算**。

### 6.2 金额：整数 milli `_milli`

`1000 milli = 1 积分`。**禁止浮点**参与余额、单价、扣费、套餐积分的任何计算。

```js
balance = balance - credit_per_reply                    // ❌ 1.1 - 0.1 = 1.0000000000000002
const charged_milli = unit_milli * confirmed_count      // ✅ 整数乘法
const replies_affordable = Math.floor(balance_milli / unit_milli)
```

展示时才除以 1000 并保留一位小数。`credit_per_reply` 可配 0.1–1000、步进 0.1，落库与传输**只出现 `credit_per_reply_milli`**。

### 6.3 HMAC 签名：请求与响应都要签

```js
// shared/lib/stable-stringify.js —— 签名用的确定性序列化
function stableStringify(v) {
  if (v === null || typeof v !== 'object') return JSON.stringify(v)
  if (Array.isArray(v)) return '[' + v.map(stableStringify).join(',') + ']'
  const keys = Object.keys(v).filter(k => v[k] !== undefined).sort()                        // 递归按 key 升序
  return '{' + keys.map(k => JSON.stringify(k) + ':' + stableStringify(v[k])).join(',') + '}'
}
```

**实现要求**：递归按 key 升序、无空格、不排序数组；`undefined` 键丢弃（与 `JSON.stringify` 一致）；遇循环引用抛 `TypeError`（属 bug 而非数据）；**不做**数字归一化（`1.0` 与 `1` 序列化不同，调用方必须传整数）。

**两套用途不要混**：请求/响应签名串是对**原始字节**算 `sha256_hex`，**不得反序列化后重新序列化再算哈希**；`stableStringify` 只用于 `login_proof`（`protocol.md` §4.1）这类需要跨进程一致序列化的场景。

```js
// license/sign.js
const sha256_hex = (b) => crypto.createHash('sha256').update(b).digest('hex')
const hmac_hex = (k, s) => crypto.createHmac('sha256', k).update(s, 'utf8').digest('hex')

function build_signed_request(method, path_with_query, body_object, ctx) {
  const raw_body = body_object === undefined ? '' : JSON.stringify(body_object)      // 只序列化一次
  const ts_ms = now_ms(), nonce = crypto.randomBytes(8).toString('hex')             // nonce 每次必须新生成
  const canonical = [method.toUpperCase(), path_with_query, String(ts_ms), nonce,
                     sha256_hex(Buffer.from(raw_body, 'utf8'))].join('\n')
  return { raw_body, nonce, path: path_with_query, headers: {
    'Content-Type': 'application/json; charset=utf-8', 'Authorization': 'Bearer ' + ctx.token,
    'X-Lic-Ts': String(ts_ms), 'X-Lic-Nonce': nonce, 'X-Lic-Sign': hmac_hex(ctx.sign_key, canonical) } }
}

function verify_response(resp, ctx) {          // ⚠️ 校验通过前不得解析业务字段
  const got = resp.headers['x-lic-sign'], server_ts = Number(resp.headers['x-lic-server-ts'])
  if (!got || !Number.isFinite(server_ts)) return { ok: false, code: 'RESP_SIGN_MISSING' }
  if (Math.abs(now_ms() - server_ts) > ctx.sign_ts_tolerance_ms) return { ok: false, code: 'RESP_TS_SKEW' }
  const canonical = ['RESP', String(resp.status), resp.path, resp.nonce, String(server_ts),
                     sha256_hex(Buffer.from(resp.raw_body, 'utf8'))].join('\n')
  const a = Buffer.from(hmac_hex(ctx.sign_key, canonical), 'hex'), b = Buffer.from(got, 'hex')
  if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) return { ok: false, code: 'RESP_SIGN_INVALID' }
  return { ok: true, body: JSON.parse(resp.raw_body) }
}
```

⚠️ **客户端必须校验服务端响应签名**：

- 除 `POST /auth/login` 与 `GET /client/bootstrap`（不签名）外**所有响应都要验签**，**错误响应（402/409/4xx/5xx）也必须验签**——否则无法区分"服务端说余额不足/策略收紧"与"中间人伪造"。
- 验签失败 → `fail('RESP_SIGN_INVALID', { stage: STAGES.REPORT, retry: SECURITY })` → 记安全事件 → **立即 fail-closed 暂停发送** → 退避重试登录。**绝不认为余额充足、绝不认为策略放宽。**
- 比较必须用 `timingSafeEqual` 且**先比长度**（长度不等会抛异常）。
- `login_proof` 用 PBKDF2 派生密钥（`pbkdf2Sync(password, 'dsh-login|'+account+'|'+device_id, 100000, 32, 'sha256')`），校验范围排除 `login_proof` 自身；失败则**拒绝登录且不落盘任何凭据**。

### 6.4 幂等键：`send_id` 必须在发送前生成并落盘

```
发送前：生成 send_id → 原子写 pending_sends.json（fsync）→ 标记 sending → 才发起发送
发送后：拿到平台响应 → 更新同一条记录的 verdict / evidence → 服务端 ACK 后才删除
崩溃后：重启复用落盘的 send_id，attempt_seq += 1，绝不重新生成
```

```js
const send_id = 's-' + crypto.randomUUID().replace(/-/g, '')       // 协议允许 uuid v4 或 32 hex
await store.update(instance_dir, 'pending_sends.json', (d) => {     // ① 先落盘
  d.sends.push({ send_id, sent_at_ms: now_ms(), source_type: 'comment',
    target_hash, user_key_hash, user_key_type: 'sec_uid',
    verdict: 'pending', is_final: false, evidence: { confirm_signal: 'none' },
    failure_reason: null, attempt_seq: 1, applied_policy_version: policy.policy_version })
  return d
})
await guard.assert_can_send('comment')                              // ② 再校验额度（防越权）
const evidence = await platform_send(/* … */)                       // ③ 最后才真的发
```

**其他幂等键**：`batch_id`、`report_id`、`change_id`、`request_id` 各自唯一。`seq` 是**通道内自 1 递增**（`channel ∈ heartbeat/usage/sends/config_audit`，各通道独立计数）；**禁止复用 nonce**（会被判 `AUTH_REPLAY` 并触发安全告警）。

⚠️ **`platform_endpoint` 是契约闭集，不等于"已验证可用"**：`protocol.md` §4.8 白名单只有 `comment/publish`、`comment/reply`、`im/send`、`live/comment/send`，其中**仅 `comment/publish` 被 legacy 真机验证过**。私信与弹幕的真实路径片段与成功码字段必须先按 `shared/已知陷阱与平台知识.md` §3.5 手工确认再入注册表，**禁止凭猜测填写**（猜错会让成功判定恒为 false，表现为"像风控"，实际是关键字写错）。扩大闭集必须先上线服务端支持，再提升 `min_client_version`。

### 6.5 超时、重试与退避

| 场景 | 超时 | 重试 | 退避 |
|---|---|---|---|
| CDP 命令 | 8–10 s（`Runtime.evaluate` 10 s） | 1 次 | 立即 |
| 平台响应等待（`comment/publish`） | 10 s | **0 次**（空响应直接判失败） | — |
| 元素出现等待 | 每步 5–8 s，总预算 30 s | ≤3 次 | 1s / 2s / 4s |
| HTTP 业务接口 | 15 s | 按 §2.5 | 指数 1/2/4/8…上限 60 s，**加 ±20% 抖动** |
| 心跳 | — | 持续 | 指数，上限 60 s；连续 3 次未成功判离线 |
| 登录 | 20 s | 是 | 指数；`AUTH_ACCOUNT_LOCKED` 按 `retry_after_ms` 倒计时 |
| 离线补报 | 30 s | 是 | 恢复后立即补报，单批 ≤ `audit_batch_max`(500) |

**退避必须加抖动**，否则多实例客户端会在同一时刻同时重试形成尖峰。`AUTH_TS_SKEW` **只允许重试一次**（先校准 `clock_skew_ms`）。给商家的**发送间隔随机化与本节的网络退避是两件事**，不得混用同一函数（发送间隔用对数正态分布）。

## 七、安全编码规范

### 7.1 ⚠️ 本地控制台必须绑 `127.0.0.1`

```js
const HOST = process.env.REPLY_BIND_HOST || '127.0.0.1'          // ❌ 绝不是 '0.0.0.0'
if (HOST !== '127.0.0.1' && HOST !== '::1') throw new Error('本地控制台只允许绑回环地址')
http.createServer(handler).listen(PORT, HOST)
```

**旧代码事实**：`server.js:673` `listen(PORT, "0.0.0.0")` + 零鉴权 + `server.js:195-198` `Access-Control-Allow-Origin: *`（D-6）。后果：**局域网内任何人可访问控制台；任意网页可跨站调用 `POST /api/reply` 直接以商家身份发出评论**。新实现必须同时满足**绑回环 + 会话鉴权 + CORS 白名单**，三条缺一不可。

### 7.2 CORS 白名单

```js
const ALLOW_ORIGINS = new Set([`http://127.0.0.1:${PORT}`, `http://localhost:${PORT}`, 'null'])  // null = file:// 载入的本地 UI
function apply_cors(req, res) {
  const origin = req.headers.origin
  if (!origin) return                                        // 同源或非浏览器请求
  if (!ALLOW_ORIGINS.has(origin)) { res.writeHead(403); return res.end() }
  res.setHeader('Access-Control-Allow-Origin', origin)        // 回显具体来源，绝不写 '*'
  res.setHeader('Vary', 'Origin')
  res.setHeader('Access-Control-Allow-Methods', 'GET,POST,OPTIONS')
  res.setHeader('Access-Control-Allow-Headers', 'Content-Type,Authorization')
  res.setHeader('Access-Control-Allow-Credentials', 'true')
}
```

**禁止** `Access-Control-Allow-Origin: *`；禁止同时用通配来源与 `Allow-Credentials: true`；写操作接口必须校验会话令牌 + **一次性 CSRF token**（自定义头，浏览器跨站无法伪造）。

### 7.3 密码：`crypto.scrypt` 加盐哈希

```js
// license-server/crypto/password.js。scrypt(N=16384, r=8, p=1, keylen=32, salt=16B 随机)
function hash_password(plain) {
  const salt = crypto.randomBytes(16)
  const hash = crypto.scryptSync(plain, salt, 32, { N: 16384, r: 8, p: 1 })
  return `scrypt$16384$8$1$${salt.toString('hex')}$${hash.toString('hex')}`
}
function verify_password(plain, stored) {
  const [algo, n, r, p, salt_hex, hash_hex] = String(stored).split('$')
  if (algo !== 'scrypt') return false
  const expect = Buffer.from(hash_hex, 'hex')
  const actual = crypto.scryptSync(plain, Buffer.from(salt_hex, 'hex'), expect.length, { N: +n, r: +r, p: +p })
  return actual.length === expect.length && crypto.timingSafeEqual(actual, expect)
}
```

**禁止**：明文入库、MD5/SHA1、可逆加密、用 `===` 比较哈希。登录失败按账号维度计数，**5 次锁 10 分钟**；**账号不存在 / 密码错误 / 已停用 / 已到期必须返回不同错误码**（`AUTH_ACCOUNT_NOT_FOUND` / `AUTH_PASSWORD_WRONG` / `AUTH_ACCOUNT_DISABLED` / `AUTH_ACCOUNT_EXPIRED`）。

### 7.4 敏感配置走 `.env`

| 项 | 位置 | 入库 | 入日志 |
|---|---|---|---|
| `master_secret`（签名主密钥） | `.env` | 否 | 绝不 |
| 数据库路径、端口、时区偏移 | `.env` | 否 | 可以 |
| 密码哈希、`sign_key` 哈希、卡密哈希 | 数据库（**只存哈希**） | 是 | 绝不 |
| `token` / `sign_key` / `privacy_salt` | 客户端 `license_state.json`（受保护目录） | 不适用 | 绝不 |

`.env` 必须进 `.gitignore`；仓库只提交 `.env.example`（键名 + 占位值 + 注释，**不含真实值**）。启动时校验必需键，缺失时**明确列出缺失键名**，不得静默用默认密钥启动。

### 7.5 子进程调用不得拼接 shell 字符串

```js
child_process.exec(`node ${WORKSPACE}\\reply_worker.js ${taskId}`)          // ❌ 可注入 + 空格路径出错
execFile(process.execPath, [path.join(WORKSPACE, 'client', 'adapters', 'reply-comment.js'), task_id],
         { cwd: WORKSPACE, shell: false, windowsHide: true, timeout: 60000 }, cb)   // ✅ 参数数组
```

其他硬要求：子进程句柄必须由调度器持有（旧代码 D-10 丢失句柄导致扫描任务**无法停止**，只能重启整个服务）；重复启动同一任务必须**幂等拒绝并提示**（旧代码 D-13 会静默杀掉前一次）；子进程崩溃必须归因并回退任务，不得让 `running:true` 永久卡死（D-11）。

## 八、依赖与版本管理

### 8.1 白名单只有 `ws`

```json
{ "engines": { "node": ">=22.5" }, "dependencies": { "ws": "^8.18.0" },
  "scripts": { "check": "node test/check-syntax.js", "test": "node test/run.js" } }
```

`license-server` 的 `dependencies` 必须为空对象（零第三方依赖）。**引入新依赖的报备流程（四步，缺一不可）**：① 在 `shared/术语与选型基准.md` §3.2 依赖清单新增一行，写明用途与"为什么内置模块做不到"；② 同步 `README-DEV.md` §八；③ 技术负责人书面同意（提交信息注明同意记录）；④ 更新本文件 §1.4。**未走流程引入依赖的提交一律拒绝合入。**

分发影响：`ws` 推荐**随包内置**（把 `node_modules/ws` 一起打包），商家仍是"解压即用"；启动脚本加依赖自检，缺失时明确提示而非崩溃。

### 8.2 明确排除 `puppeteer-core` / `playwright`

| 理由 | 说明 |
|---|---|
| 自动化指纹 | Puppeteer 会设置 `navigator.webdriver = true` 等特征，抖音风控可识别。本项目走裸 CDP + `--disable-blink-features=AutomationControlled` |
| 用不上已登录的商家账号 | 两者默认启动**全新浏览器上下文**，用不上商家 Chrome 里已扫码登录的抖音账号；在自动化浏览器里重新登录**恰是风控最敏感的特征**。登录态真实可用是方案可行性的前提 |
| 交互原语要全部重写 | 现有 DOM 定位表达式围绕裸 CDP 的 `Runtime.evaluate` 编写，换到 `page.evaluate` 模型要重写全部交互原语——这正是最值钱的部分 |
| 版本绑定与体积 | 绑定特定 Chrome 版本，增大分发包 |

同理不引入：任何前端框架、任何 ORM、`better-sqlite3`（需编译原生模块，环境易失败；`node:sqlite` 已够用）。WebSocket 服务端（如需要）也用 `ws`，不自研。

### 8.3 Node 版本自检

```js
const MIN = [22, 5, 0], cur = process.versions.node.split('.').map(Number)
if (cur[0] < MIN[0] || (cur[0] === MIN[0] && cur[1] < MIN[1])) {
  console.error(`本程序需要 Node.js ≥ ${MIN.join('.')}（当前 ${process.versions.node}）。`)
  console.error('服务端需要内置 node:sqlite（Node 22.5 引入）。请升级后重试。')
  process.exit(2)                       // 唯一允许的 exit：环境不满足，明确告知而非崩溃
}
try { require('node:sqlite') } catch { console.error('当前 Node 未提供 node:sqlite，请升级到 ≥ 22.5。'); process.exit(2) }
```

`process.exit` 仅允许用于：Node 版本/依赖自检失败、强制升级页、`cli.js` 的一次性命令。**业务运行期禁止**（§2.6）。
