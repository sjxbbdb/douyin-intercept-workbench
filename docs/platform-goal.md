# 平台侧交付目标（v4）

本文是平台侧的执行合同。它描述授权端、可分发桌面端和 Agent 编排要达到的行为；视频搜索、评论区、直播间适配器由协作者提供，平台只负责把它们放进受控的固定流程。

## 交付边界

平台侧必须交付以下能力：

1. Linux 服务端是授权、账密、设备上限、有效期、功能开关、积分价格、积分台账、策略版本、运行实例、人工恢复和审计的唯一权威。
2. Windows 客户端只保存加密会话材料，通过窄 preload IPC 调用主进程；renderer 不接触 token、provider key、平台 cookie 或 localStorage。
3. 一个 Agent 聊天入口完成意图识别、参数补全和固定流程选择。模型只能返回已注册的 `workflowId/version/params`，不能返回步骤、脚本或发送指令。
4. 固定流程由确定性执行器运行。流程为 `RUNNING` 时不调用模型，也不允许模型改写步骤；流程结束后才把结构化结果交给模型，模型只能选择允许的下一状态。
5. 每个运行实例绑定工作台账号、设备、抖音平台账号、策略版本、知识集版本和幂等键。账号切换、授权失效、积分不足、能力撤销或浏览器异常会暂停对应账号的实例。
6. 所有付费动作使用服务端价格、短期预留、提交/释放、幂等键和审计；未知结果保留原操作 ID，不换键重发，不自动把未知改成成功。
7. 恢复状态机使用有限重试和递增间隔；达到阈值后固化检查点、通知人工。人工确认并通过两次健康检查后，继续原实例，不创建替代实例。副作用动作进入 `UNKNOWN` 后必须先查询或人工核对。
8. 话术知识库按租户隔离并绑定版本。当前的 token-bag 检索只是可验证的离线后端，不能对外宣称已经部署生产向量数据库；真实向量后端接入前保持明确的 provider/version/evidence 字段。
9. 桌面工作台保持窄而清晰的入口：Agent、找视频、评论区、直播间、任务/恢复、话术库、积分和设置；所有知识库/账号/恢复操作由主进程代持授权，renderer 不持有 token。

## 固定业务流程的承载契约

平台不决定协作者如何采集页面，只提供流程边界和能力门禁：

- `video.search`：关键词 → 候选视频 → 游标分页 → 证据和检查点。
- `comment.reply_then_private`：关键词筛选评论 → 公屏回复 → 仅对服务端/适配器确认成功的公屏目标私信。公屏未确认时私信步骤被阻断。
- `comment.batch`：采集评论 → 冻结关键词和话术 → 批量公屏回复 → 逐条确认成功 → 只对本批次确认成功目标私信 → 生成批次台账；部分成功可以继续，未知目标不能盲重发。
- `live.batch`：直播间关键词匹配 → 公屏回复 → 仅对确认成功的目标私信。批次必须有边界、TTL 和可恢复台账；`live.reply_then_private` 保留为单条目标的同序固定流程。

这三个流程由服务端注册版本和发行开关控制。缺少真实页面、真实账号或官方权限证据时，发送能力的 `autoEligible` 必须为 `false`；离线 fixture、构建成功和 DOM 表象不能作为送达证据。

## 状态与故障边界

服务端接受的流程状态为 `PLANNED`、`RUNNING`、`CHECKPOINT`、`UNKNOWN`、`WAITING_HUMAN`、`PAUSED`、`COMPLETED`、`FAILED`、`STOPPED`。发送动作另有 `sent_confirmed`、`sent_unknown`、`blocked` 和 `failed` 语义。网络超时、进程崩溃、页面变化、登录失效、验证码、权限拒绝和响应不可解析都不能直接产生 `COMPLETED`。

恢复必须记录：原运行 ID、原步骤、操作 ID、幂等键、检查点版本、适配器版本、能力证据摘要、失败码、重试次数和人工确认者。所有 checkpoint、lease、credit action、send operation 和人工动作都写审计；日志只保存脱敏标识和 hash。

## 开发顺序和验收门

1. 服务端：数据库迁移、策略/能力目录、积分动作授权、幂等和过期回收、运行实例重检、恢复证据、审计查询。
2. 桌面端：启动恢复、专用浏览器异常收敛、账号切换隔离、Agent 聊天和固定流程边界、人工恢复入口。
3. 共享契约：sidecar 能力声明、操作结果、发送确认、未知查询和版本兼容。
4. 发行与运维：Linux 安装包、Windows portable/NSIS 包、临时文件落盘路径、CI、备份恢复和脱敏诊断。
5. 验收：`server` 在 Ubuntu build/test，`desktop` 在 Windows check/test/build；随后使用 fake sidecar 做协议和恢复测试；最后再单独记录真实抖音账号、页面版本、官方资格、真实支付和生产部署证据。

每一项功能必须同时给出代码、测试、失败状态、证据来源和发行条件。没有证据的能力只能展示为“未验证/人工模式”，不能开放自动发送。
