## 一、这个项目是什么

一套**抖音互动自动化工具**，帮助商家自动回复视频评论、直播间弹幕与私信，并把互动中的意向客户沉淀为线索名单。采用「客户端 + 授权中心」两段式架构，按**成功回复条数**计费。

驱动方式为 Chrome 远程调试协议（CDP），使用商家本机**已登录的**专用 Chrome，因此登录态真实可用。

## 二、⚠️ 先读这一段：三条不可违背的红线

在写任何代码之前，请先理解并接受以下三条。**它们不是建议，是产品存在的前提。**

### 红线 1：安全上限由服务端下发，客户端不可绕过

**背景**：这个工具的价值来自"发得多"，而账号被封的原因也是"发得多"。这两个目标根本对立。

因此产品定位是**「控制节奏，让账号活得久」**，不是"发得越多越好"。所有安全上限（日发送量、最小间隔、活跃时段、内容相似度）**由服务端权威下发，客户端只能调低不能调高**。

- 权威数值见 `shared/protocol.md` §4.6 的 `tier_table`（**全系统唯一来源**）
- 越权上报 → 服务端返回 `POLICY_VIOLATION(409)` 并拒绝
- 新账号前 3 天为**观察期，日上限为 0**（只采集、不发送），客户端**不可跳过**

> **如果实现时放宽了这些限制，整个项目就失去了核心价值，且会产生真实的账号封禁损失。**

### 红线 2：只对平台确认成功的发送计费

计费依据**仅有** `POST /api/v1/audit/sends` 的逐条明细，且必须**同时**满足：

```
verdict = sent_confirmed
且 confirm_signal = platform_response      ← DOM 判断不算，必须拿到平台响应
且 platform_status_code = 0
且 未超当日策略上限
且 该 send_id 未计费过
```

失败、被风控拒绝、被跳过、超上限的发送**一律不计费**。

> **特别注意**：绝不允许"DOM 上看起来发出去了"就判定成功。旧代码中曾出现"编辑器消失即判定已发送"的错误（把页面崩溃记为成功），必须避免。空响应 = 风控拒绝，不得标记成功。

### 红线 3：审计留痕必须记录"真实生效的策略值"

每次发送与配置变更都要留痕，且审计必须记录**实际生效的策略版本与生效值**，而不只是用户设置值。

原因：纠纷时需要能回答"该账号当时实际生效的策略是什么、用户是否主动调高过、系统是否拒绝过"。**只记设置值无法自证。**

- 隐私边界：**只上传哈希与计数，绝不上传评论原文、回复内容原文、用户隐私字段**
- 审计本地与服务端双写，客户端不可篡改服务端副本

更多合规要求见 `shared/安全与合规要求.md`。

### 关于 `legacy/`

原项目是**别人的半成品**，存在 14 项已确认缺陷（含硬编码绝对路径导致在非原作者机器上跑不通、队列竞态丢任务、控制台裸奔可被跨站调用等）。完整清单见 `docs/平台需求规格.md` §五（已转为设计反面教材，每条对应一项新架构约束）。

**处置决定：完全重写。** 但——旧代码**不删除**，已移入 `legacy/` 作为**只读行为规格参考**。

**为什么必须保留**：旧代码里含有用真账号在真页面上反复试错换来的**抖音 DOM 知识**（例如：页面上同时存在隐藏与可见两个 `comment-list`，只能用可见的那个；`scrollIntoView` 之后虚拟列表会重渲染，必须延迟再读按钮坐标否则拿到 0×0）。这些知识**无法凭空复现**，且每次试错都消耗真实账号风险。

**使用方式**：

1. 新实现的每个 DOM 交互原语，都要在 `legacy/` 中找到对应实现逐条对照
2. 已提取的知识点见 `shared/已知陷阱与平台知识.md`（**写 DOM 代码前必读**）
3. 离线回归测试见 `shared/测试策略.md`

**⚠️ 硬约束**：`legacy/` **只读**，不得被任何生产代码 `require`。这是验收项之一。

## 五、⚠️ 项目定位已于 2026-09-19 修正（**先读这一节**）

> ### 原定位：一个"抖音自动回复工具"
> ### 现定位：**一个可承载多种专业分化工作流的 Agent 平台**，"抖音截流"是它的第一个内置工作流包
>
> **完整依据**：`plans/ADR-001-Agent优先与框架选型.md`

### 这个修正改变了什么

| 维度 | 修正前 | 修正后 |
|---|---|---|
| **Agent** | 可选增值项，"以后再加的一层" | **承载形态**，默认开启；关闭后退化为纯工具链路（降级路径） |
| **行业知识** | 硬编码在 `adapters/` 里 | 由**工作流包**声明，核心不预设任何行业 |
| **加新领域** | 改核心代码 | **加一个包**（`plans/C-工作流包契约.md`） |
| **交互主入口** | 图形界面（填表单、点按钮） | **对话界面**；图形界面成为降级路径与精细操作入口 |
| **计费** | 只有"按成功条数" | 按 `action_kind` 分派（`send` / `compute` / `llm`），为需求 5 的自动剪辑预留 |
| **依赖白名单** | 仅 `ws` | `ws` + `@langchain/langgraph` + `zod`（**服务端仍为零依赖**） |

### ⚠️ 原"先做 A，后评估 B"的路线**已作废**

作废的**不是**"顺序"，而是把 Agent 定位成**后续叠加的一层**。
正确的关系不是"A → 然后 A + Agent"，而是：

```
        ┌──────────────────────────────────────────────────────┐
        │  工作流包（声明式）                                    │
        │  douyin-intercept/ · 你的领域/ · …                    │
        │  线索判据 · 业务规则 · 话术池 · 合规边界 · 成功定义      │
        └───────────────────────┬──────────────────────────────┘
                                │ 单向收窄（只能更保守）
        ┌───────────────────────▼──────────────────────────────┐
        │  Agent 层（LangGraph 状态图，默认开启）                │
        │  理解意图 → 编排步骤 → 🔴 硬闸门（代码 if）→ 汇报        │
        └───────────────────────┬──────────────────────────────┘
                                │ 进程内调用
        ┌───────────────────────▼──────────────────────────────┐
        │  既有底座（已完成，约 33,000 行，复用率 97%）          │
        │  授权中心 · 契约 · 计费 · 审计 · 策略下发              │
        │  core(CDP) · platform(选择器) · adapters · safety     │
        │  license · host(store/queue/scheduler) · ui           │
        └──────────────────────────────────────────────────────┘
```

**方案 A 的形态没有被浪费**——它成为**降级路径**：Agent 不可用、超预算、误批率超标时，
商家仍能用图形界面完成全部工作（`plans/B-与方案A的差异说明.md` §3.4 的四条理由**全部继续成立**）。

## 八、技术选型（速查）

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Node.js ≥ 22.5**（客户端与服务端均要求） | 服务端需 `node:sqlite` |
| 语言 | **纯 JavaScript**（不用 TypeScript，无构建步骤） | 零构建便于商家分发；如需 TS 需自行评估 |
| CDP WebSocket | **`ws`** | 自研需处理分帧/背压/重连/半开连接，是"要求稳定"最不该自己写的部分 |
| **Agent 编排** | **`@langchain/langgraph`** | 实测 **22 包 / 47.6 MB**，CommonJS 直接 `require` 无构建。项目的硬需求"状态落盘、崩溃可续、闸门不可跳过"正是其检查点的原生能力 |
| **工具参数校验** | **`zod`** | langgraph 的 peer dependency。**必须显式声明，不留隐式依赖** |
| HTTP 服务 | **Node 内置 `http`** | 够用 |
| 服务端存储 | **`node:sqlite`（内置）** | 真事务、零依赖。已实测可用 |
| 客户端存储 | **JSON 文件 + 单写者 + 原子写** | 见 `docs/架构说明.md` §八 |
| 密码哈希 | **内置 `crypto.scrypt`** | 够用 |
| HMAC | **内置 `crypto.createHmac`** | 够用 |
| LLM 调用 | **内置 `node:https` 自研适配器** | 只是"一个 POST、一个 JSON"。**不得引入模型厂商 SDK** |
| 前端 | **原生 DOM，无框架** | 保持单文件分发，无构建。见 `shared/术语与选型基准.md` §3.2.1 |

**明确不引入**：`puppeteer-core` / `playwright`（给浏览器打自动化指纹，且**用不上商家已登录的账号**）、
`@mastra/core`（152 包 / 104.4 MB）、任何需要构建步骤的依赖、任何 ORM。
**服务端依赖：零**（此条不放宽）。理由见 `shared/术语与选型基准.md` §3.2 §3.3。
