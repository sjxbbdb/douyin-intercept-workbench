## 4. 原子链路方法（关键实现点）

### 4.1 定位三原则

1. **只认可见节点**：页面上常同时存在隐藏与可见两份同名容器（两个 comment-list、两个 im-dialog）。
   `querySelector` 可能拿到隐藏那份（宽度 0）→ 必须遍历取宽度最大者。
2. **原子操作**：找到元素 → 滚入视口 → 点击 → 检测结果，必须在同一次 `Runtime.evaluate` 内完成。
   分两次调用时，中间会经历虚拟列表重渲染，节点已被回收（表现为「说找到了、紧接着说按钮找不到」）。
3. **DOM click 兜底**：几何定位失败时直接 `element.click()`，不要求元素在视口内（React 会响应非可信 click）。

### 4.2 文本匹配三坑

| 坑 | 现象 | 修法 |
|---|---|---|
| 零宽字符 | 昵称/正文混入 U+200B–U+200F、U+034F，比对永不等 | 两侧剔除；昵称只作优先项，不作硬条件 |
| 表情标记 | 目标文本把 [流泪] 整段删掉，页面文本只删方括号 → 对不上 | 页面侧同样整段删 [xxx] |
| 多条同文评论 | 复制粘贴导致 XPath 兜底可能匹配到别人 | 文本兜底仅在唯一命中时采用，歧义即放弃 |

### 4.3 评论关键词匹配模式（本轮新增）

| 模式 | 行为 | 适用 |
|---|---|---|
| char | 关键词拆成单字，命中任意一个字即入选 | 召回优先，**噪音极大**（求带/手里有资金/111 → 求/带/手/里/有/资/金/1） |
| segment | 整串或二字词命中；纯数字关键词不切分（111 不匹配 211） | 平衡 |
| **phrase** | 必须字面包含完整关键词 | 推荐；本轮采用，入队前断言 0 条不符 |

## 5. 失败状态（全部如实记录，不谎报成功）

| 失败标识 | 含义 | 处置 |
|---|---|---|
| `comment_not_rendered` | 评论在接口响应里有，但网页版评论区不渲染（已删除/被折叠） | 标记跳过，不重试 |
| `reply POST not captured` | 编辑器已打开、文案已输入、回车已发，但平台未接收 | 判为风控静默拦截；放慢节奏后同批全部成功 |
| `publish 被拒绝（空响应）` | 同上，另一判定分支 | 如实标失败，不进入 done |
| `private_account` | 主页命中「私密账号/该用户已设置私密/暂不公开」 | 打开主页阶段即跳过，不点私信 |
| `私信输入框未出现` | 面板未展开（标签页被判不可见等） | 如实记失败，附原因 |

### 5.1 节奏实测（重要运营结论）

- 同一账号、同一批线索：间隔 35–65 秒 / 每批 9 条 → 连续 `reply POST not captured`；
- 间隔 45–80 秒 / 每批 3–5 条 → **同样 5 条线索全部发送成功**；
- 结论：**不是功能问题，是节奏问题**。建议默认 `REPLY_GAP_MIN_MS=45000`、`REPLY_MAX_PER_RUN=5`。

3. **未覆盖验证码/滑块场景**：遇到即停，不做识别或绕过（与仓库红线一致）。
4. **窗口可见性依赖**：标签页被完全遮挡时私信面板可能不展开，当前如实记失败；彻底解法需独立 Chrome 实例启动参数，未验证。

## 7. 发行开关条件（建议）

- 评论回复、私信发送**默认关闭**，需显式开启（与 probe 现有 `--allow-send` 口径一致）；
- 开启前必须满足：① 单批上限 ≤5 ② 间隔 ≥45 秒 ③ 每日配额上限（建议 20）

- 未满足上述条件的构建**不得**把发送能力标为可用。
