## 二、沙箱内 git 推送失败（两层原因，缺一不可）

命令: git -c http.sslBackend=openssl push -u origin feat/keyword-video-comment-crawl
exit = 128
fatal: could not read Username for 'https://github.com': terminal prompts disabled

1) 传输层 —— git 默认用 schannel 后端：
     schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)
   改用 git 自带的 OpenSSL 后端（-c http.sslBackend=openssl）后可以连通 GitHub。
   （另有 MSYS 提示 could not create signal pipe, Win32 error 5 —— 沙箱禁止命名管道，不影响本结论。）

2) 凭据层 —— 运行环境内不存在任何 GitHub 凭据：
     GITHUB_TOKEN=False   GH_TOKEN=False   ~/.git-credentials=False   ~/.ssh=False   gh CLI=False
   且目标仓库为私有（api.github.com/repos/sjxbbdb/douyin-intercept-workbench 匿名返回 404）。

## 五、教训（写下来避免重犯）

提交前**必须先对齐远端基线**（git fetch / 用 API 取 base sha 并对比），
否则会在一个已经包含该功能的基线上，提交一份「看起来是新功能、实际是回退」的 diff。
本次本地克隆停在 74cb9b7，而远端已到 f1c7d50 —— 两者相差了整个 probe/ 的落地。
