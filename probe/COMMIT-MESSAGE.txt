feat(probe): 关键词搜视频 → 评论采集 → 评论关键词筛选 → 私信队列

新增独立、零第三方依赖的 Python 工具包 probe/，实现截流链路前四步：

  1. 按视频关键词搜视频 —— 读平台搜索接口响应体（general/search/single），
     DOM 瀑布流只做兜底；卡片 DOM 里连 a 链接都没有，接口字段是结构化。
  2. 抓取视频评论 —— 读 comment/list 接口响应体，comments[].user.sec_uid 直接可得；
     记录器锁死本次 aweme_id，避免串入推荐视频的评论。
  3. 按评论关键词筛选 —— 四档语义 phrase / seg(默认) / all / any，
     每次运行同时打印四档命中数（实测 284 条评论：11/11/0/77）。
  4. 产出私信队列 —— 按 sec_uid 去重 + 点赞阈值。

另含可选的私信执行器（默认只预填不发送，必须显式 --allow-send）。

零第三方依赖：只用 Python 标准库，自带最小 RFC6455 WebSocket（dsh_ws.py），
不需要 websockets / playwright / puppeteer，保持裸 CDP、不打自动化指纹。

真机验证（真实账号 · Chrome 153.0.8010.50）：
  · 关键词「宝宝辅食」搜到 83 条视频（10 个接口响应，status_code 非 0 的 0 个）
  · 3 条视频共 284 条评论，sec_uid 完整率 100%；单条 505 评论的视频实抓 191 条
  · seg 档命中 11 条 -> 队列 11 人
  · 私信 9/9 送达（sent_dom_confirmed）

真机修正过的问题（详见 PR-BODY.md §6，源码注释里均留档）：
  · Network 域未打开 -> 接口响应体永远 0 条且不报错
  · 登录判据用正文匹配 -> 被视频简介「一旦退出登录后…」误判为未登录；改 cookie 判据
  · 验证码判据命中预埋的空容器 -> 正常页面被误判；改为「可见且里面有东西」+ OOPIF frame 判据
  · 评论容器坐标固定在 (900,500) -> 滚的是整页而不是评论列表
  · 接口正文带表情 / DOM 正文丢表情 -> 同一条评论收两次；改前缀包含去重（280 -> 257）
  · 窗口被遮挡 -> visibilityState=hidden，点击不送达渲染进程且不报错（同关键词 83 条 vs 9 条）
  · 额度闸只认 sent_confirmed -> 同一人 10 分钟内被发两条、每日上限从未生效
  · 「文案出现在面板里」分不清送达与被平台拒绝 -> 先判拒绝文案再判成功
  · 本目录 selectors.py 顶掉标准库同名模块 -> 改名 dyselectors.py
